# 冷蔵庫コンパス — 冷蔵庫管理アプリ プロトタイプ

要件定義書（概要）に基づく動作プロトタイプ。純粋な HTML/CSS/JavaScript 製で、ビルド不要。

## 起動方法

任意の静的サーバーでこのフォルダを配信するだけです。

```
python -m http.server 8650 --directory fridge-app
# → http://localhost:8650 を開く
```

（`index.html` をブラウザで直接開いても動作します）

## 実装済み機能と要件の対応

| 要件 | 実装 | 備考 |
|---|---|---|
| 手入力登録 | ✅ | 食材名・数量・カテゴリ・賞味期限。カテゴリ選択で期限の目安を自動セット |
| レシート撮影登録（OCR） | ✅ モック | 撮影/選択後に解析演出→サンプル6品を抽出。カテゴリ別デフォルト期限を自動セットし、登録前に編集可能 |
| バーコードスキャン登録 | ✅ モック | JANコード辞書（6商品）で商品名を特定。スキャンシミュレートボタンあり |
| 在庫一覧（期限順ソート・強調表示） | ✅ | 期限切れ/3日以内を色分け。名前順・登録順ソートも可 |
| 賞味期限アラート（3日前通知） | ✅ モック | 起動時にバナー表示。設定画面で通知時刻を設定（実プッシュ通知は未実装） |
| AIレシピ提案（在庫優先） | ✅ モック | レシピDB＋スコアリング（期限が近い食材ほど高評価）で上位3件を提案。「AIが考案」の演出付き |
| 参照URLの提示 | ✅ | 各レシピにクックパッド/クラシルの検索URLを添付 |
| 不足食材の提示 | ✅ | 在庫にない材料を赤チップで明示 |
| 買い物リスト ワンタップ追加 | ✅ | 不足食材をボタン1つでリストへ。手動メモ追加も可 |
| 在庫データ自動連動 | ✅ | 「購入済み」チェックで在庫へ数量1・カテゴリ推定・デフォルト期限付きで自動加算 |

## プロトタイプの割り切り（本実装時の置き換えポイント）

- **OCR**: `startOcr()` が固定サンプルを返す → Google Cloud Vision / Claude API 等の画像解析に置き換え
- **バーコード**: `JAN_DB` の静的辞書 → JANコードDB API（例: Yahoo!商品検索、JICFS）＋カメラ読取ライブラリ（例: ZXing）
- **AIレシピ生成**: `rankRecipes()` のルールベーススコアリング → Claude API 等の生成AI呼び出し（在庫＋期限をプロンプトに渡す）
- **プッシュ通知**: バナー表示のみ → Service Worker + Web Push（または モバイルアプリ化して FCM/APNs）
- **データ保存**: localStorage → バックエンドAPI + DB（複数端末同期する場合）

## iPhone で使う（PWA）

Apple Developer Program（年$99）も Mac も不要で、iPhone にアプリとして入れられます。
HTTPS で公開して Safari の「ホーム画面に追加」を使う方式です。
→ 手順は **[DEPLOY_iOS.md](DEPLOY_iOS.md)** を参照。

- Service Worker によりオフラインでも全機能が動作
- ホーム画面から全画面起動（ノッチ/ホームバー対応済み）
- iOS で開くと「ホーム画面に追加」の案内バナーを表示

## ファイル構成

- `index.html` — 画面構造（在庫 / レシピ提案 / 買い物リスト / 設定 の4タブ＋モーダル3種）
- `styles.css` — スタイル（スマホ想定 max-width 480px）
- `app.js` — 全ロジック。データは localStorage キー `fridge-compass-v1` に保存
- `pwa.js` — Service Worker 登録・iOS インストール案内
- `sw.js` — Service Worker（オフラインキャッシュ）
- `manifest.webmanifest` — PWA マニフェスト
- `icons/` — アプリアイコン（`make_icons.py` で生成）

設定画面の「データを初期化」でいつでもサンプルデータに戻せます。
